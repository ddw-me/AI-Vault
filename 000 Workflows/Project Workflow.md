# Project Workflow

Use a project note when work needs more than one day's attention, has several meaningful steps, involves dependencies or follow-ups, or needs context that would make a daily note difficult to scan.

Keep the daily note as the place where work is captured. The project note is the place where multi-day work is organized. Link between them so the current action is visible in the daily note without copying the entire project history.

## Start a project

1. Capture the request or idea in the daily note.
2. Decide whether it needs a project. Do not create one just to give a small task a more impressive name.
3. Create a note in `Active Projects/` from [Project Template](../Templates/Project%20Template.md).
4. Record only known information. Leave unknown dates, owners, stakeholders, and outcomes blank.
5. Define a completion condition when it becomes clear.
6. Add a link or short pointer to the project from the daily note.

## Project statuses

- **Draft:** The idea or request is captured, but the purpose, ownership, or next action is not confirmed.
- **Active:** Work is currently progressing and has a next action.
- **Waiting:** The next step depends on another person, an external event, or information that is not yet available. Record what is awaited and when to follow up.
- **Complete:** The completion condition has been met. Record the outcome and date rather than only changing the status.
- **Cancelled:** The work is intentionally stopped or no longer needed. Record the reason when it is useful.

Use one current status at a time. A proposed date, milestone, or estimate is not a commitment until the user confirms it.

## Work the project

- Keep the next action concrete and small enough to start.
- Record important decisions, progress, blockers, and changes in direction in the project note.
- Capture daily activity in the daily note and summarize meaningful progress in the project note.
- Use `Waiting` when someone else owns the next step; do not disguise waiting as active work.
- Review stale projects during the weekly review. Ask whether to continue, revise, wait, cancel, or complete them.

## Complete or cancel a project

Before changing a project to `Complete`, check its completion condition and record the result. Before changing it to `Cancelled`, record what was decided and why when that context may matter later.

After a project is complete or cancelled, create `Active Projects/Archive/` if needed and move the note there when the active folder should remain focused on current work. If you use Obsidian, move the note from within Obsidian with automatic internal-link updating enabled in **Settings → Files and Links**. Then check incoming links, relative outgoing links, and attachments. Preserve links and history. If the project is still useful as reference material, keep the note or add a link from the relevant reference note.

Archiving is a filing decision, not deletion. Do not delete the project note merely because the work is finished.
