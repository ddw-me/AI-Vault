# Time Management in Practice

This note shows how the vault's pieces can work together during an ordinary week. The example is fictional. It demonstrates the pattern without prescribing a particular schedule or requiring every note, plugin, Git operation, or AI interaction.

## How the pieces fit

| Piece | Purpose |
|---|---|
| Markdown notes | Preserve useful information, decisions, and next actions in records the user owns |
| Obsidian | Make those notes convenient to write, connect, and find |
| Daily, weekly, and monthly routines | Keep commitments current and connect immediate work to longer-term goals |
| Git | Preserve recoverable versions of the notes |
| AI and instruction files | Help interpret the record and propose work within clear boundaries |

The point is not to operate every part perfectly. Each piece should reduce the effort of remembering, resuming, and deciding what matters next.

## A fictional example week

### Longer-term direction

- **Goal:** Become more confident giving technical presentations.
- **This month's focus:** Prepare one short workshop.
- **Project:** Prepare the workshop with a clear audience, intended outcome, and next action.

### Monday

The person checks the calendar, reviews the most recent daily note, and chooses **outline three main points** as the Daily Frog. They create or update the workshop project note and leave a pointer in the daily note.

During the day, a request changes the intended audience. The person records the request and the decision about the audience rather than trusting memory.

### Tuesday

The person reviews the previous note, chooses the next action, and continues the outline. The project note records meaningful progress while the daily note captures what happened today and what should happen next.

### Wednesday

Life interrupts the plan. There is no daily note. This is not a failure and does not require inventing a record later.

### Thursday

The person returns by opening today's note and reviewing the most recent useful earlier note. They carry forward only the workshop action that still matters. They do not reconstruct Wednesday. If a short backfilled note would be useful, they may create one from remembered or verified information, but it is optional.

### End of the week

The person reviews the available daily notes and the workshop project. They record what moved forward, what remains open, and the next useful action. If the notes are valuable enough to preserve, they make a Git checkpoint. The weekly review uses the available evidence and identifies any missing days rather than pretending the record is complete.

### End of the month

The monthly review asks whether the workshop advanced the longer-term goal. The person chooses whether to continue, revise, pause, or stop the effort and records the next useful step if it continues.

### Optional AI assistance

An AI assistant may read the same available notes and workflow instructions, identify missing context, and suggest a realistic plan. The assistant should not invent what happened on Wednesday, decide the person's priorities, or imply that a suggestion was saved as a note.

## Returning after a gap

Daily notes are useful, but they are not a streak or a test. People get sick, travel, handle urgent life events, or simply have days when writing is not possible. The system should make returning easy.

When returning:

1. Start with today's note.
2. Review the most recent useful earlier note.
3. Carry forward only commitments that still matter.
4. Replan, delegate, schedule, or drop items deliberately.
5. Backfill missed days only when doing so helps, using remembered or verified information.

Do not let the desire to catch up prevent a return to the notes. A sparse daily note still preserves useful context, and a gap is better than abandoning the system because the record is not perfect.
